# Dependency and licensing audit

This audit covers the repository state on **2026-08-12**. The authoritative
inputs are the [Cargo workspace manifest](../Cargo.toml), the
[core crate manifest](../crates/gpu-core/Cargo.toml), the
[NAPI crate manifest](../crates/gpu-napi/Cargo.toml), the
[workspace npm manifest](../package.json), and the
[public package manifest](../packages/gpu/package.json). Versions below are the
exact direct requirements in those files; transitive Rust resolutions are
recorded in [Cargo.lock](../Cargo.lock).

The audit is descriptive, not legal advice. Before a release, generate a
third-party notice from the resolved production graph and have counsel review
the use of undocumented Apple APIs and any future vendor SDK headers.

## Runtime policy and terminology

- The production telemetry path does not invoke `nvidia-smi`, `amd-smi`,
  `intel_gpu_top`, `powermetrics`, or any other executable. A source scan found
  no subprocess launch in a provider. JavaScript's `process.report` and Rust's
  `std::process::id()` are in-process APIs, not subprocesses.
- **Compiled in** means Rust code is incorporated into the `.node` addon and
  introduces no separately installed runtime library.
- **OS hard link** means an import of a library/framework that is part of the
  target operating system. It does not mean a GPU-vendor runtime is bundled.
- **Dynamic** means an optional library is opened at runtime. Absence must be
  reported through capabilities/diagnostics and must not prevent addon loading.
- Unless a row says otherwise, the dependency does not shell out, does not need
  root/administrator privileges, and is suitable for every architecture on
  which its containing crate/package is built.
- Driver and kernel permissions can still make an individual metric
  unavailable. The library does not ask users to elevate privileges to work
  around that condition.

## Redistribution checklist

1. Publish the JavaScript package plus exactly one matching optional native
   package per supported target; do not put driver libraries in either package.
2. Include this project's MIT license and a generated third-party notice covering
   the resolved Rust code compiled into each addon. Honor the selected branch of
   every `OR` license expression consistently.
3. Do not redistribute NVML, ADLX, AMD SMI, Level Zero, Apple frameworks, or
   kernel libraries. They are host/driver components.
4. Re-run the dependency/license/advisory audit whenever a manifest, feature set,
   target, vendored header, or generated binding changes.
5. Any future GPL/LGPL dependency, vendor SDK header copy, or hard-linked optional
   runtime requires an explicit architecture and legal review before merge.

## Reproducibility notes

- Cargo direct requirements are exact and the full Rust graph is locked in
  `Cargo.lock`.
- The npm manifests use exact direct versions and the full JavaScript graph is
  recorded in `pnpm-lock.yaml`. CI/release installs use the frozen lockfile and
  do not run dependency lifecycle scripts.
- The workspace resolves transitive `esbuild` to `0.28.2`, excluding
  GHSA-g7r4-m6w7-qqqr in the Windows-only development-server surface. Neither
  esbuild nor the development server ships in the public package.
- The 2026-08-12 scans found no known vulnerabilities with `pnpm audit
--audit-level low` or `cargo audit`. RustSec emitted only the documented
  macOS `paste` maintenance warning.
